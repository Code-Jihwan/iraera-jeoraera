# 나만의 유행어 (가칭) — 내 말투 × 떠오르는 밈

정예공군팀(AI·SW마에스트로 17기) 기획안의 MVP 사용자 흐름 다섯 단계를 그대로 실행하는 웹 서비스입니다.

**말투 등록 → 말투 프로필 → 트렌드 고르기 → 유행어 생성 → 반응·공유**

API 키가 하나도 없어도 예시 트렌드 데이터와 규칙 기반 기본 엔진으로 끝까지 동작하고, 키를 넣으면 AI 엔진(Claude)과 실제 트렌드 수집(YouTube Data API)으로 바뀝니다.

## 실행

Node.js 22 이상이 필요합니다.

```bash
npm install
```

```bash
npm start
```

- 사용자 화면: http://localhost:3000/
- 운영 화면(성공 지표·트렌드 검수·신고): http://localhost:3000/ops.html
- 테스트: `npm test`

설정은 `.env.example`을 `.env`로 복사해 필요한 값만 채웁니다.

| 넣는 값 | 바뀌는 것 |
| --- | --- |
| (없음) | 예시 트렌드 26건 + 규칙 기반 기본 엔진 |
| `ANTHROPIC_API_KEY` | 유행어를 AI 엔진(기본 `claude-opus-5-5`)으로 만들고, AI 안전 심사를 함께 돌림 |
| `YOUTUBE_API_KEY` | YouTube 인기 차트의 제목·태그에서 키워드를 주기적으로 수집 (기본은 운영 화면에서 승인해야 노출) |
| `IG_ACCESS_TOKEN` + `IG_USER_ID` | 수집한 키워드의 인스타그램 해시태그 반응 확인(7일 30개 한도 관리) |
| `ADMIN_TOKEN` | 운영 화면을 원격에서 열 때 필요한 토큰 (없으면 이 컴퓨터에서 `localhost`로 직접 연 경우에만 열림) |
| `EVENT_RETENTION_DAYS` · `REPORT_RETENTION_DAYS` | 서버에 남는 생성·반응 기록과 신고의 보관 일수(기본 90일). 화면 고지 문구도 이 값을 따름 |
| `TRUST_PROXY=true` | 같은 컴퓨터의 HTTPS 프록시 뒤에서 돌릴 때 손님 주소를 `X-Forwarded-For`로 구분 |
| `GENERATE_DAILY_LIMIT_PER_CLIENT` | 손님(IP, IPv6는 /64) 한 명이 하루에 만들 수 있는 횟수(기본 60) |

마이크(음성 녹음)는 브라우저 정책상 `localhost` 또는 HTTPS에서만 동작합니다. 다른 기기에서 쓰려면 HTTPS 프록시(nginx, Caddy 등) 뒤에 두고 `PUBLIC_HOSTS`, `ADMIN_TOKEN`, `TRUST_PROXY`를 함께 설정하세요.

AI 엔진을 켜면(키를 넣으면) 프로필 요약이 국외(Anthropic, 미국)로 전송되므로, 기본 엔진일 때 동의한 사용자도 다음에 쓸 때 국외 이전 안내를 보고 다시 동의하게 됩니다.

## GitHub Pages(정적 데모)

서버 없이 브라우저만으로 도는 데모를 GitHub Pages에 올립니다.

- 주소: https://code-jihwan.github.io/iraera-jeoraera/

서버 모드(`npm start`)와 다른 점:

- **기본 엔진(규칙 기반)만 씁니다.** API 키를 브라우저에 둘 수 없어서 AI 엔진(Claude)은 쓰지 않습니다. 생성 엔진과 금칙어 필터는 서버와 같은 코드를 브라우저에서 돌립니다.
- **예시 트렌드만 있습니다.** 빌드할 때 `server/trends/seed-trends.json`을 `data/trends.json`으로 묶어 싣습니다. YouTube·Instagram 수집은 없습니다.
- **서버 기록·운영 화면이 없습니다.** 생성·반응 기록을 남기지 않고, 운영 화면(`ops.html`)은 싣지 않으며, 신고는 화면에서 그 문구를 빼기만 할 뿐 누구에게도 전달되지 않습니다.
- **데이터는 브라우저에만 남습니다.** 입력한 글, 음성 분석 결과, 프로필, 결과, 반응, 신고가 어디로도 전송되지 않습니다(받아쓰기는 브라우저의 음성 인식 기능을 씀). 화면의 고지 문구도 정적 모드에 맞게 바뀝니다.
- 사이트 파일은 GitHub Pages가 내려 주므로, GitHub가 접속 기록(IP 주소 등)을 [GitHub 개인정보처리방침](https://docs.github.com/site-policy/privacy-policies/github-general-privacy-statement)에 따라 처리할 수 있습니다. 이 안내는 이용 안내 화면과 동의 화면에도 있습니다.

배포 방식:

1. `main`에 push하면 GitHub Actions(`.github/workflows/pages.yml`)가 테스트(`npm test`) → 정적 빌드(`npm run build:static`) → 배포 순서로 돕니다. Actions 탭에서 직접 돌릴 수도 있습니다(workflow_dispatch).
2. 처음 한 번만 저장소 **Settings → Pages → Source**를 **GitHub Actions**로 바꿔 둡니다.

내 컴퓨터에서 확인하기:

```bash
npm run build:static     # dist/에 정적 사이트를 만들고 경로·파일을 검사
npm run preview:static   # 프로젝트 사이트처럼 하위 경로(/preview/) 아래에 띄움
```

브라우저에서 http://127.0.0.1:4173/preview/ 를 엽니다(`PORT`, `BASE`, `DIR` 환경변수로 바꿀 수 있음). 빌드는 모든 경로가 상대 경로인지, 대소문자까지 맞는 파일을 가리키는지(GitHub Pages는 대소문자를 가림), 서버 전용 파일이 섞이지 않았는지 검사하고 문제가 있으면 실패합니다. 결과물 폴더는 지우고 새로 만들기 때문에, 저장소 원본 폴더·홈 폴더·`.git`이나 `package.json`이 있는 폴더·비어 있지 않고 예전 빌드 결과물(`.nojekyll`)도 아닌 폴더는 거절합니다(링크를 따라간 실제 경로로 검사).

GitHub Pages는 응답 헤더를 정할 수 없어 서버 모드의 `X-Frame-Options`·`frame-ancestors` 같은 프레임 차단을 보낼 수 없습니다(`<meta>` CSP의 `frame-ancestors`는 무시됨). 대신 정적 데모는 다른 페이지의 프레임 안에서 열리면 앱을 띄우지 않고 새 창으로 여는 링크만 보여 줍니다(클릭재킹 방지).

주의: `code-jihwan.github.io` 아래의 Pages 사이트는 모두 같은 출처(origin)라서 브라우저 저장 공간(localStorage 등)을 함께 씁니다. 같은 계정의 다른 Pages 사이트가 이 데모의 저장 내용을 읽을 수 있다는 뜻이므로, 분리하려면 사용자 지정 도메인을 연결하세요.

## 구조

기획안의 시스템 구조(말투 분석과 트렌드 수집을 따로 돌리고 생성 엔진에서 합침)를 따릅니다.

```
public/            사용자 화면(빌드 없는 ES 모듈) · 운영 화면
  js/views/        다섯 단계 화면 + 보관함 · 내 데이터 · 이용 안내
  js/voice.js      녹음: 음성 인식(받아쓰기) + 음량으로 말 리듬 측정 — 원본 음성은 저장하지 않음
shared/            브라우저와 서버가 함께 쓰는 모듈
  style-analyzer.js  말투 특징 추출(어미·표현·추임새·웃음 습관·리듬) → 말투 프로필
  kakao-parser.js    카카오톡 내보내기 파일에서 본인 발화만 추출
  rhythm.js · hangul.js · pii.js
server/
  http.js · api.js   API 서버(요청 제한, 보안 헤더, 출처 검사)
  generate/          생성 엔진: ① 프롬프트 구성 ② LLM 생성(없으면 규칙 엔진) ③ 안전 필터 ④ 랭킹
  safety/            금칙어 필터(트렌드 단계 1차 필터 + 생성 단계 필터)
  trends/            트렌드 수집 배치: YouTube 인기 차트 → 키워드 추출 → 정제·중복 제거 → 금칙어 필터 → 검수 → 노출
  events.js          반응 기록과 성공 지표 계산
scripts/           정적 데모 빌드(build-static.mjs)와 하위 경로 미리 보기 서버(preview-static.mjs)
data/              실행 중 생기는 파일(트렌드 캐시, 반응 기록, 신고) — 저장소에 올리지 않음
```

### 개인정보를 다루는 방식

- 말투 분석은 **브라우저 안에서** 합니다. 붙여 넣은 원문과 대화 파일은 서버로 보내지 않고 분석 직후 지웁니다.
- 말투 프로필은 **사용자의 브라우저(localStorage)에만** 저장합니다. 서버는 유행어를 만드는 동안에만 프로필 요약을 쓰고 저장하지 않습니다.
- 카카오톡 파일은 사용자가 고른 이름의 메시지만 남기고 나머지는 바로 버립니다.
- 녹음은 `MediaRecorder`를 쓰지 않습니다. 받아쓴 글과 말 빠르기·쉼 수치만 남고, 화자 식별용 정보는 만들지 않습니다.
- 음성 동의를 거두면 녹음 중이던 것과 아직 분석하지 않은 녹음 결과를 버리고, 프로필에서 목소리로만 찾은 말버릇·받아쓴 대표 문장·말 리듬을 지웁니다(대표 문장마다 글/말 출처를 기록).
- 서버 기록(`data/events.jsonl`)에는 생성·반응의 종류·시각·요청 번호와 익명 ID만 남고 문구·프로필 내용은 남지 않습니다. 신고된 문구·사유·덧붙인 말만 검토용으로 따로 저장하며(연락처 같은 부분은 가림), 모두 보관 기간(기본 90일)이 지나면 매시간 도는 정리 작업이 지웁니다.
- 반응·신고는 서버가 실제로 만들어 준 생성 요청과 그 후보 번호에 대해서만 받아, 지표를 함부로 부풀릴 수 없습니다. 예시 말투로 만든 결과의 평가는 ‘내 말투 같다’ 지표에서 따로 셉니다.
- 결과 카드에는 ‘AI 생성’ 배지를, 공유 이미지와 복사한 글에는 ‘AI 생성’ 표시를 넣습니다.

## 기획안의 “결정 필요” 항목을 이렇게 정했습니다

팀에서 바꾸기 쉽도록 대부분 `shared/constants.js`와 환경변수 한 곳에 모았습니다.

| 항목 | 정한 값 | 바꾸는 곳 |
| --- | --- | --- |
| 서비스명 | ‘나만의 유행어’(가칭, 발표자료 문구) | `SERVICE_NAME` |
| 웹·앱 형태 | 반응형 웹(설치 없이 모바일·PC) | — |
| 녹음 길이 | 권장 30~60초, 최소 15초, 최대 90초 | `LIMITS.voice` |
| 텍스트 분량 | 최소 200자, 권장 1,000자 이상, 최대 20,000자 | `LIMITS.text` |
| 생성 후보 개수 | 5개, 후보마다 예문 2개 | `LIMITS.candidates` |
| 가입 연령 | 만 14세 이상만(자기 확인 체크) | `MIN_AGE` |
| 트렌드 갱신 주기 | 3시간 | `TREND_REFRESH_MINUTES` |
| 트렌드 보관 | 7일(YouTube 정책상 30일 이내) | `TREND_TTL_DAYS` |
| 트렌드 검수 | 사람이 승인한 뒤 노출 | `TREND_REVIEW_MODE` |
| LLM | Claude(`claude-opus-5-5`), 안전 심사 포함 | `LLM_MODEL` 등 |
| STT | 브라우저 음성 인식(Web Speech API) — 별도 STT 서버 없음 | `public/js/voice.js` |
| 저장소 | 프로필은 브라우저, 서버는 파일(JSON) | `server/store.js` |
| 성공 지표 목표 | 말투 4.0점 · 저장·공유 30% · 반영 24시간 · 유해 1% (임시값) | `TARGET_*` |

## 조사하면서 확인한 것 — 출시 전에 팀이 꼭 봐야 할 점

2026-11-11 기준 공식 문서를 확인한 결과입니다. 법률·정책 판단은 전문가 검토가 필요합니다.

1. **YouTube 인기 차트는 밈 신호로 약합니다.** 2025-07-21부터 `chart=mostPopular`는 음악·영화·게임 인기 차트 영상을 돌려줍니다. 기획안의 “API 인기 차트가 밈 흐름을 담는지 검증”은 실제 키로 PoC를 해 봐야 합니다. 어떤 카테고리에 차트가 있는지도 문서에 없어 실행 중에 확인하도록 만들었습니다.
2. **YouTube API 정책이 파생 지표와 타 플랫폼 결합을 제한합니다.** 개발자 정책 III.E.4.h(API 데이터로 새 지표·파생 데이터 생성 금지), III.E.2(집계 금지), 준수 가이드(다른 데이터와 결합 금지)에 걸릴 수 있습니다. 그래서 조회수 등 통계는 아예 받지 않고, 차트 순서와 영상 수만으로 정렬하며, 인스타그램 수치는 섞지 않고 따로 표시합니다. 그래도 “제목·태그에서 키워드를 뽑는 것”과 “그 키워드로 인스타그램을 조회하는 것” 자체가 허용되는지는 정책 검토가 필요합니다.
3. **YouTube API를 쓰면 고지 의무가 생깁니다.** YouTube 서비스 약관 링크, Google 개인정보처리방침 링크, YouTube API 서비스 이용 사실을 이용 안내에 넣었습니다. 출처 표시는 지금 글자 링크이며, 정식 출시 때는 브랜딩 가이드에 맞는 YouTube 로고가 필요할 수 있습니다.
4. **인스타그램 해시태그 검색은 문턱이 높습니다.** 비즈니스·크리에이터 계정, 앱 심사, 비즈니스 인증이 필요하고, 허용 용도가 브랜드·캠페인 분석 위주라 이 서비스의 용도가 승인될지 불확실합니다. 코드는 공식 문서대로 만들었지만 **실제 토큰으로는 검증하지 못했습니다.**
5. **브라우저 음성 인식은 브라우저마다 다릅니다.** 크롬은 기본적으로 음성을 구글 서버로 보내 받아씁니다(기기 내 인식 팩이 설치돼 있으면 기기 안에서 처리). 사파리는 Siri 받아쓰기를 쓰고, 파이어폭스는 160부터 기기 내 인식만 지원합니다. 모바일에서는 마이크를 음성 인식과 음량 측정이 함께 쓸 수 없어 말 리듬 수치가 빠집니다. 동의 문구에 이 사실을 넣었지만, 이것이 처리위탁·국외 이전 고지 대상인지는 검토가 필요합니다.
6. **AI 엔진을 켜면 국외 이전 고지가 필요합니다.** 프로필 요약이 Anthropic(미국) API로 전송됩니다. 동의 화면과 이용 안내에 표를 넣었고, 보유 기간 등 사업자 약관에 달린 값은 `[운영자 확인 필요]`로 표시해 두었습니다.
7. **고지·동의 문구는 초안입니다.** 개인정보 보호법 제15조·제22조·제22조의2·제28조의8, 인공지능기본법 제31조 체크리스트에 맞춰 썼지만 법률 검토 전입니다(`public/js/notices.js`).
8. **예시 트렌드는 2026-11-11 시점 자료입니다.** 공개 기사·사전으로 뜻과 유래를 확인한 22개 밈과 계절 키워드 4개입니다. 실시간 순위가 아니고, 시간이 지나면 다시 확인해야 합니다(`server/trends/seed-trends.json`).

## 기본 엔진과 AI 엔진

- **기본 엔진(규칙 기반)**: 예시 트렌드에 붙여 둔 활용 정보(어간, 높임 단계별 완성형, 빈칸)에 내 어미·추임새·웃음 습관·리듬을 입힙니다. 키 없이 동작을 보여 주기 위한 것이라 표현 폭은 좁습니다.
- **AI 엔진**: 말투 프로필 요약과 트렌드를 프롬프트로 구성해 후보를 만들고, 금칙어 필터와 AI 안전 심사를 통과한 것만 랭킹해 보여 줍니다. 호출이 실패하거나 심사가 응답하지 않으면 기본 엔진 결과로 바꿔서 보여 줍니다(심사 실패 시 AI 결과는 내보내지 않음).
- 좋아요·별로예요는 만드는 방식(어미 입히기, 추임새 얹기, 내 단어 넣기, 줄임·합성, 리듬 맞추기, 비틀기)별로 쌓여 다음 랭킹과 프롬프트에 반영됩니다.

## 검증한 범위

- 자동 테스트 847개(`npm test`): 말투 분석기, 카카오톡 파서, 안전 필터, 트렌드 수집(가짜 응답으로), 생성 엔진, 음성 리듬 분석, HTTP 보안, 반응 기록·지표, 서버 전체 흐름, 정적 데모 빌드와 브라우저 안 백엔드(서버와 같은 응답 모양·오류 문구인지 견줌). 모듈마다 독립 검증자가 공격 테스트를 따로 써서 찾은 결함을 고쳤습니다.
